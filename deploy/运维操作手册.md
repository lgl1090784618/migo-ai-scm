# 运维操作手册（小白版）

> 给没有运维经验的人看的「日常操作指南」。只要会复制粘贴命令，就能完成日常检查、看日志、重启、备份。
> 前提：你已经能登录服务器（见 §1）。密码/密钥一律不在本文档明文，实际值找管理员要。

## 0. 先记住这几个位置

| 东西 | 位置 | 说明 |
| --- | --- | --- |
| 网站入口 | `https://192.168.10.154:8443/` | 浏览器打开看界面 |
| 程序目录 | `/opt/mossdoom/current` | 当前正在跑的版本（是个符号链接） |
| 数据目录 | `/srv/mossdoom/` | 数据库、对象存储、备份都在这里 |
| 凭据目录 | `/etc/mossdoom/` | 各种密码/密钥（secrets）+ 证书（tls） |
| 项目名 | `mossdoom-test` | docker compose 的项目名 |

## 1. 怎么登录服务器

在你自己电脑的终端（Windows 用 PowerShell 或 CMD）执行：

```bash
ssh -i E:\codex-private\credentials\mossdoom\test-154-automation migo@192.168.10.154
```

登录成功后，命令提示符会变成 `migo@...:~$`，说明你已经在服务器上了。

> 注意：下面所有 `sudo docker` 命令都要在**服务器上**执行，不是在你电脑上。

## 2. 怎么看服务是否正常（日常巡检，3 分钟）

### 2.1 看网站能不能打开

浏览器访问 `https://192.168.10.154:8443/`，能打开登录页就是正常。

### 2.2 看 6 个容器都在跑

```bash
sudo docker ps
```

正常应该看到 6 个服务，`STATUS` 都是 `Up`（运行中）：

| 容器名 | 干什么 |
| --- | --- |
| `mossdoom-test-app-1` | 后端应用（核心） |
| `mossdoom-test-web-1` | Nginx 网关（对外入口） |
| `mossdoom-test-postgres-1` | 数据库 |
| `mossdoom-test-objectstore-1` | 对象存储（SeaweedFS） |
| `mossdoom-test-prometheus-1` | 监控 |
| `mossdoom-test-node-exporter-1` | 服务器资源监控 |

如果某个服务没有出现，或 `STATUS` 不是 `Up`，就是它挂了，见 §5。

### 2.3 看应用健康状态（最直接的体检）

```bash
sudo docker exec mossdoom-test-web-1 wget -qO- http://app:8080/actuator/health
```

返回 `{"status":"UP"}` 就是健康；返回 `DOWN` 或报错就是有问题。

## 3. 怎么看日志（排障必学）

### 3.1 看应用日志（后端）

```bash
# 看最近 200 行
sudo docker logs --tail 200 mossdoom-test-app-1

# 实时跟着看（按 Ctrl+C 退出）
sudo docker logs -f mossdoom-test-app-1
```

### 3.2 看其他服务日志

把上面的 `mossdoom-test-app-1` 换成别的容器名即可，例如：

```bash
sudo docker logs --tail 100 mossdoom-test-postgres-1   # 数据库日志
sudo docker logs --tail 100 mossdoom-test-web-1        # 网关日志
sudo docker logs --tail 100 mossdoom-test-objectstore-1 # 对象存储日志
```

### 3.3 日志里找错误

```bash
sudo docker logs mossdoom-test-app-1 2>&1 | grep -i error
```

## 4. 怎么重启（最常用的修复手段）

### 4.1 只重启应用（最常用，数据不受影响）

```bash
cd /opt/mossdoom/current
sudo docker compose restart app
```

### 4.2 重启全部服务（数据不受影响，但会短暂中断访问）

```bash
cd /opt/mossdoom/current
sudo docker compose restart
```

### 4.3 彻底重建（配置改了才用，数据不受影响）

```bash
cd /opt/mossdoom/current
sudo docker compose up -d
```

## 5. 常见问题排查

### 问题 A：网站打不开 / 502

1. 先看容器状态：`sudo docker ps`（确认 web 和 app 都在 Up）。
2. 看应用日志：`sudo docker logs --tail 100 mossdoom-test-app-1`。
3. 看健康状态：`sudo docker exec mossdoom-test-web-1 wget -qO- http://app:8080/actuator/health`。
4. 重启应用：`cd /opt/mossdoom/current && sudo docker compose restart app`。

### 问题 B：登录提示账号密码错误

- 确认账号：管理员是 `admin`，只读用户是 `viewer`。
- 密码在服务器 `/etc/mossdoom/secrets/app_admin_password`（管理员）和 `app_viewer_password`（只读用户）文件里。
- 读取：`sudo cat /etc/mossdoom/secrets/app_admin_password`

### 问题 C：磁盘满了（最常见的隐患）

```bash
df -h
```

看 `/`（根分区）和 `/srv` 的使用率。如果接近 100%，先看是哪里占的：

```bash
sudo du -sh /srv/mossdoom/*   # 看数据目录谁最大
sudo du -sh /srv/mossdoom/backups/*  # 备份目录通常最占空间
```

备份目录可以清理旧备份（见 §6.3），但**清理前先确认不是唯一副本**。

### 问题 D：数据库连不上

先确认数据库容器在跑：`sudo docker ps | grep postgres`

如果在跑但连不上，看日志：`sudo docker logs --tail 100 mossdoom-test-postgres-1`

> 提示：数据库不映射宿主机端口，是**故意**的安全设计。想用工具（DBeaver/Navicat）连库，见《部署与迁移手册》§5 的 SSH 隧道方法。

## 6. 备份与恢复（最重要，定期做）

### 6.1 手动备份一次

```bash
cd /opt/mossdoom/current
sudo bash backup.sh
```

备份结果在 `/srv/mossdoom/backups/` 目录。

### 6.2 备份了什么

- PostgreSQL 两个库（采集库 + 业务库）
- 对象存储数据（原文事件字节）

### 6.3 清理旧备份（省磁盘）

```bash
ls -lt /srv/mossdoom/backups/    # 按时间倒序看备份
```

删除 N 天前的旧备份（**务必确认是旧备份、且最新备份完好后再删**）：

```bash
sudo find /srv/mossdoom/backups/ -type f -mtime +30 -delete   # 删 30 天前的
```

### 6.4 恢复

完整的恢复步骤见《部署与迁移手册》§8（跨服务器迁移/恢复），核心是：

```bash
sudo docker exec -i mossdoom-test-postgres-1 pg_restore -U moss_admin -d moss_ingestion --clean < ingestion.dump
```

> **警告**：恢复是破坏性操作（会覆盖当前数据），新手不要单独执行，先找熟悉的人一起。
