# 测试记录：可拖拽卡片与布局模板（2026-11-12）

> 对象：测试机 https://192.168.10.154:8443 「经营总览」页
> 版本：`index-CKv8MWl7.js`（提交 `0c111db` + 布局弹回修复）
> 方式：`agent-browser`（Chromium）+ **真实鼠标事件**（CDP `Input.dispatchMouseEvent`），非合成 `PointerEvent`

## 一、为什么重测

首轮自测用的是页面内合成的 `PointerEvent`，且只挑了「全宽卡片」横向拖动验证——全宽卡片受 12 列栅格约束，x 恒为 0，即使逻辑有错也看不出来。用真实鼠标重测后发现真问题：

**缺陷（已修）**：松手时执行「向下避让 + 向上压实」，导致把卡片往下拖到空白处后会立刻弹回顶部，用户观感就是「拖不动」。
**修复**：`resolveDown(items, priorityId?)` 只做重叠避让与向下推挤，不再向上压实；被拖动的卡片优先占位，其余依次下移。加载已保存布局时同样只避让不压实，否则刷新后位置也会被拉回顶部。

## 三、判定为正确行为的两个「看起来像 bug」

- 把半宽卡片拖到右列会与同排另一张卡片重叠 → 后者被推到下一行（y+10），两张都在右列。这是「落点优先、其余下移」的设计结果，不是错位。
- 拖动后页面出现空白区域属正常（不做向上压实，等同 Grafana 的自由布局语义）。

## 四、补测结果（2026-11-12 11:00–11:20）

1. **多用户隔离（已补测，通过）**：`verify-dashboard-isolation.py` 11 项断言全通过——admin 看不到 viewer 的模板、viewer 看不到 admin 的模板、`owner` 按登录用户返回、同名模板在不同 owner 下互不覆盖、越界布局对两种角色都返回 400、匿名读布局返回 401、清理后无残留。
   - 附带发现：`VIEWER` 角色**可以**保存/删除自己的看板模板（`PUT/DELETE /api/dashboards` 允许 ADMIN 与 VIEWER）。布局是个人视图，这样处理是合理的；如果之后希望 viewer 只读，需要在 `DashboardController` 收紧到 ADMIN。
2. **窄屏（已补测并修复）**：原实现 <1100px 时仍按 12 列压，卡片被挤成细条、内容区出横向滚动。
   - 修复：`grid.tsx` 增加容器宽度测量，`< 900px` 时放弃绝对定位，改为 `.dash-stack` 单列流式排列，卡片高度自适应（不再内部滚动），按保存的 y/x 顺序铺开；同时隐藏拖拽手柄并提示「窗口较窄，已自动单列排列」。
   - 实测 780×700：6 张卡全部单列、宽度等于画布宽、`scrollHeight-clientHeight` 全为 0（无内部滚动）、高度 286/356/207/207/568/429；回到 1264 宽自动恢复 12 列栅格（6 卡、5 行、3 张半宽）。
   - 编辑态在窄屏：手柄与拖拽图标均为 0，提示文案正常，避免误操作。
