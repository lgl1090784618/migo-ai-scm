# 主体框架说明

## 已明确并实现的边界

平台目录、连接实例、数据集、结构版本、映射版本、采集身份、接收批次、事件原料、处理任务、通用投影、异常与审计相互分离。新增平台和字段通过配置及新版本扩展；发布版本不可修改，历史批次绑定接收时的版本。管理操作使用乐观版本检查；列表使用有界游标分页，批量操作只处理明确选中的最多100条记录。

前端提供运行概览、平台与连接、数据集与版本、接收批次、处理任务、异常数据和审计日志七个页面。没有模拟的经营指标。预置的平台目录只是平台分类，不代表已经连通。连接配置目前登记后只读，修改配置需新登记连接；结构或映射调整通过新版本发布。

首版只允许启用 test 环境的 PUSH 接收连接。HTTP、MCP、数据库、文件和 Agent 类型可以登记，PULL 主动连接器尚未执行。不同机器上的 Agent、Skill、定时脚本可通过统一 HTTPS 接收协议提交；当前未实现 MCP 服务端或各平台 SDK、签名器和增量游标。

## 实际处理链路

1. 采集令牌绑定租户、连接和数据集；客户端不能通过请求参数改变身份范围。
2. 接收端验证协议和事件信封，原始 UTF-8 请求字节先写入 S3，并记录 SHA-256。
3. 在采集库同一事务中写入批次、事件元数据、outbox 任务和接收审计，成功后返回202。202表示已持久化接收，不代表业务处理完成。
4. worker 通过行锁、租约和递增 fencing 值领取任务，按照固定版本校验并执行声明式字段映射。
5. 在业务库同一事务中写入 inbox 和通用事件投影；重试依靠 inbox 去重。之后更新采集事件状态与批次统计。
6. 数据不符合结构、转换失败或同来源事件ID内容冲突时，保留原料并隔离该事件。存储等操作故障指数退避，最多尝试5次；失败任务支持手工重试。

业务库提交后、采集状态提交前崩溃时，恢复任务使用相同 raw_id 识别已完成投影，避免重复写入。事件去重键与投影版本区分；投影版本包含数据集、结构和映射版本。跨库采用最终一致性，没有跨库分布式事务。

## 数据库与扩展

采集库保存控制配置、批次、事件元数据、outbox、异常及审计。原始大报文进入 S3；业务库保存 inbox 与追加式通用投影，不把未知字段全部转换成宽表列。明确检索字段使用关系列，变化字段使用 JSONB。通用投影不是正式商品、库存、采购、生产、订单或利润模型，也没有自动匹配 SPU/SKU。

raw_event 已按接收时间月分区，保留当前月、次月及兜底分区。持续运行前必须补上分区维护作业；兜底不是长期容量方案。当前身份去重表、批次、审计和通用投影没有完成大规模分片，数据集详情的版本和令牌列表也尚未分页。因此不能将现有代码描述为已支持亿级生产吞吐。

后续先以实际数据量、保留周期、峰值事件率和查询分布压测，再拆分接收与 worker 进程、扩展 worker、多级队列、分区和冷热归档。按租户/来源规划分片键，分析查询达到需求后再引入 ClickHouse/Doris。MongoDB 不因来源多就默认必选；当前关系控制、事务状态、审计和 JSONB 足以实现首版，不需要4核8G同时部署三类数据库。

对象写入成功而采集事务失败，可能产生无批次引用的对象。首版不自动清理，后续加入有保护期的引用核对及清理任务。不要用“恰好一次”概括所有外部行为；目前保障的是幂等接收及业务投影去重，没有外部业务写操作。

## 安全及未实现项

当前单租户 mossdoom、管理员/只读角色和文件挂载凭据适用于测试。令牌数据库只存 SHA-256，签发时仅返回一次；吊销实时生效。管理会话与采集令牌分离，管理写接口校验 CSRF，原文仅管理员可读并留审计。日志不记录凭据、原文或 SQL 参数。

生产还需正式身份体系、权限分级、密钥托管与轮换、备份异机存储、迁移账号与运行账号分权、持续分区维护、容量/故障压测及监控通知通道。当前告警在 Prometheus 展示，未向任何人员或外部群发送通知。
