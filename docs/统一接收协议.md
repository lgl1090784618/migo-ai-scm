# 统一接收协议

当前提供 HTTPS JSON 协议，协议版本1.0。调用方可部署在不同机器上，以自身定时任务、Agent、Skill、API/数据库/文件适配器采集后提交。MCP 接收封装尚未实现。

## 配置顺序

管理员登记连接与数据集，发布 Schema（可选发布映射），显式启用 test/PUSH 连接及数据集，再签发绑定数据集的令牌。发布新结构会清空当前映射并使数据集回到待配置；发布映射同样回到待配置，检查后重新启用。历史批次保留原版本。令牌只显示一次，不应放进 Excel、普通日志或代码。

## 接收

`POST /ingestion/v1/batches`，请求头：

```text
Content-Type: application/json
Authorization: Bearer <独立采集令牌>
Idempotency-Key: <稳定批次标识>
```

```json
{
  "protocol_version": "1.0",
  "source_instance_id": "<令牌绑定的连接UUID>",
  "dataset_id": "<令牌绑定的数据集UUID>",
  "schema_version": 1,
  "events": [{
    "specversion": "1.0",
    "id": "source-event-00001",
    "source": "urn:mossdoom:source:<连接UUID>",
    "type": "inventory.snapshot",
    "time": "2026-11-10T17:00:00+08:00",
    "operation": "upsert",
    "entity_key": {"warehouse_code": "W01", "sku": "000123"},
    "data": {"sku": "000123", "quantity": 3}
  }]
}
```

示例只是信封格式；字段含义以发布的业务 Schema 为准。首版每批1–1000事件、最大5MiB、UTF-8；每令牌每分钟最多120个新批次。限制在单实例内计数，水平扩容时需改为共享限流。

信封约定采用 CloudEvents 1.0 的基本属性，并增加 entity_key/operation。实体标识为最多10个非空字符串或整数，编码建议用字符串保留前导零。upsert 表示完整快照，delete 表示保留血缘的墓碑事件；当前通用投影追加记录，不物理删除或更新经营实体。不支持 patch 和源系统回写。

HTTP202响应包含 batch_id、DURABLY_RECEIVED、processing_state、status_url 和 request_id。调用 `GET /ingestion/v1/batches/{batch_id}` 查询完成、重复及隔离计数，当前令牌只能查询自己的批次；调用 `GET /ingestion/v1/datasets/{id}/schema` 获取当前结构，只能查询令牌绑定的数据集。

同一令牌及幂等键重试相同内容返回原批次；不同内容返回409。指纹对对象字段排序，保留数组顺序和数值表示，并非完整 JSON Canonicalization Scheme。网络断开、429或503时使用原键原内容退避重试。不同批次重复事件会按来源+事件ID+内容识别；同一事件ID换内容将隔离。业务变更应产生新的事件ID。

## 校验与映射

JSON Schema2020-12受限子集支持对象、字段类型、必填、数值范围、枚举及基础数组约束。首版禁用引用、正则、组合与条件关键词，防止远程解析和不可控执行。映射为固定 JSON Pointer 加类型转换，不接受可执行脚本。

```json
{"fields":{"sku":"/goods/code","amount":"/price"},"types":{"amount":"decimal"},"includeUnmapped":false}
```

decimal使用精确十进制，精度最多38位、小数尺度绝对值最多12位；integer拒绝有小数的输入。金额推荐来源以十进制字符串提交，再显式转换，避免调用方 JavaScript 提前损失精度。原文始终保持收到的实际字节，管理投影接口额外提供 payload_text 供精确文本查看。

校验失败的事件进入异常列表，不会阻止同批其他合法事件。数据或规则调整后需提交新事件/新版本；首版手工“重试”只用于存储、处理等操作故障，不等于修改规则后的历史重放。
