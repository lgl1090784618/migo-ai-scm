# P1 设计：连接器元数据表 + 指标注册表

> 目标：把"接一个新平台要改 Java"变成"插一行配置"。参考 Airbyte 的 Declarative Manifest 思路（`streams[] → retriever → requester/authenticator/paginator → record_selector/extractor`），把它落到我们已有的 `collection_endpoint` 表上。

---

## 一、现状为什么必须改

| 位置 | 写死的内容 |
|---|---|
| `CollectionConfiguration.java:44` | `if(endpoint.equals("wms.sku-stock"))` |
| `:45-47` | 两个 18 项参数白名单字面量 |
| `:51` | 新物云请求体上限 16384、形态校验 |

## 二、Airbyte 的抽象（借鉴点）

Airbyte 的连接器用一份 YAML 描述，核心层级：

```
DeclarativeSource
└─ streams[]                      # 一个流 = 一个可采集实体
   ├─ name / primary_key          # 实体名与主键（去重依据）
   ├─ retriever
   │  ├─ requester                # 怎么发请求
   │  │  ├─ url_base / path
   │  │  ├─ http_method / request_headers / request_body_json
   │  │  └─ authenticator         # 认证：Bearer / ApiKey / OAuth / Custom
   │  ├─ paginator                # 怎么翻页：OffsetIncrement / PageIncrement / CursorPagination
   │  └─ record_selector
   │     └─ extractor             # 从响应里取数组：field_path（JSONPath）
   └─ schema_loader               # 字段结构
```

**照搬的三条**：
1. **能力声明化**——认证、翻页、抽取都是配置对象，不是代码分支；
2. **一个 stream 一个实体**——对应我们的 `dataset`（一个 dataset 一个实体）；
3. **主键显式**——`primary_key` 决定去重，对应我们 `event_identity`。

**不照搬的**：Airbyte 的 YAML 是随代码发布的静态文件；我们需要**运行时可改**（运维在界面上调），所以落库而不是落仓。

## 三、落库设计（Flyway V11）

`collection_endpoint` 现有列：`id, name, method, path, items_pointer, request_template, review_status, documentation_url, platform_code, success_code, page_field, size_field, next_pointer, total_pointer`。

新增列（全部可空，空则走默认行为，保证向后兼容）：

```sql
ALTER TABLE collection_endpoint
  ADD COLUMN request_schema   jsonb NOT NULL DEFAULT '{}'::jsonb,  -- 参数白名单与类型约束
  ADD COLUMN auth_kinds       text[]  NOT NULL DEFAULT '{}',       -- 允许的认证方式
  ADD COLUMN paging           jsonb NOT NULL DEFAULT '{}'::jsonb,  -- 翻页策略
  ADD COLUMN extract          jsonb NOT NULL DEFAULT '{}'::jsonb,  -- 响应抽取
  ADD COLUMN policy           jsonb NOT NULL DEFAULT '{}'::jsonb;  -- 限速/超时/窗口
```

字段形状（与现有 4 个端点一一对应）：

```jsonc
// request_schema —— 参数白名单（替代 CollectionConfiguration 里的 Set.of(...))
{
  "allow": ["pageIndex", "pageSize", "conditions", "orderBy"],
  "required": ["pageIndex"],
  "defaults": { "pageSize": 50 },
  "ranges": { "pageIndex": { "min": 1 }, "pageSize": { "min": 1, "max": 100 } },
  "maxBytes": 16384
}

// auth_kinds —— 认证方式（替代 startsWith("gateway.") 推导）
["BEARER", "WMS_APP", "GATEWAY_SESSION", "LOGIN_ACCOUNT", "XWY_SIGNING"]

// paging —— 翻页策略
{
  "type": "page_number",          // page_number | offset | cursor
  "pageField": "pageIndex",       // 页码参数名
  "sizeField": "pageSize",
  "startAt": 1,
  "nextPointer": "hasNext",       // 或 "/data/hasMore"
  "totalPointer": "total",
  "maxPages": 100
}

// extract —— 响应抽取（替代硬编码的 items_pointer 语义）
{
  "items": "/data/records",       // JSON Pointer
  "count": "/data/total",
  "successCode": 200,
  "successPointer": "code",       // 业务成功码字段
  "successValue": 200
}

// policy —— 运行策略
{
  "timeoutSeconds": 30,
  "maxResponseBytes": 5242880,
  "windowSeconds": 0,             // >0 表示支持滚动时间窗
  "minWindowSeconds": 60,
  "concurrency": 1,
  "rateLimitPerMinute": 30
}
```

**执行器**（新增 `CollectionExecutor`）伪代码，消灭全部 if：

```
plan   = endpoint.paging
schema = endpoint.request_schema
for page in pages(plan):
    request = validate(request_json, schema)        // 白名单+必填+范围
    auth    = SourceAuthentication.authorize(kind ∈ endpoint.auth_kinds)
    resp    = http(method, path, request, auth, policy.timeout)
    body    = limit(resp, policy.maxResponseBytes)
    items   = jsonPointer(body, extract.items)
    emit(items, entity = dataset.code, primaryKey = stream.primary_key)
    if !hasNext(body, plan) or page >= plan.maxPages: break
```

## 四、指标注册表（Flyway V12）

现状：口径写在 SQL 里（`DISTINCT ON (apply_no) ... ORDER BY occurred_at DESC` 就是"每单取最新"这条业务规则）。改口径 = 改代码。

```sql
CREATE TABLE metric (
  id            text PRIMARY KEY,              -- production.orders.latest
  name          text NOT NULL,
  unit          text,
  grain         text NOT NULL,                 -- 单 / SKU / 款号 / 日
  source_datasets text[] NOT NULL,             -- 依赖的数据集
  sql_template  text NOT NULL,                 -- 参数化 SQL（只允许 SELECT）
  dims          jsonb NOT NULL DEFAULT '[]',   -- 可用维度：店铺/地区/状态/工厂
  definition    text,                          -- 业务口径说明（人读）
  owner         text,
  enabled       boolean NOT NULL DEFAULT true,
  updated_at    timestamptz NOT NULL DEFAULT now()
);
```

接口统一：

```
GET /api/metrics                      → 列出可用指标（id/name/unit/definition）
GET /api/metrics/{id}?from=&to=&dims= → { rows, total, asOf, definition }
```

好处：
- 新增指标 = 插一行（DBA 或管理员界面），不用发版；
- 前端只认 `metric.id`，不认 SQL；
- 口径说明与实现放在一起，评审时能对着看。

## 五、迁移步骤（不破坏现网）

1. V11/V12 迁移 + 回填：把现有 4 个 endpoint 的差异写成上面的 JSON（一次性脚本，逐条核对 probe 结果不变）；
2. 新增 `CollectionExecutor`，与旧 `CollectionConfiguration` **并行**运行，用开关 `endpoint.executor = "legacy" | "metadata"` 控制；
3. 逐端点切换，每个都用 `verify-framework.py` 的 probe 断言比对（原文 SHA256 必须一致）；
4. 全部切换后删除 `CollectionConfiguration` 的 5 处 if 与 `GatewayLogin` 的前缀判断；
5. 回归：20 项端到端 + 4 源 probe。

**验收标准**：新增一个同构端点（例如领星订单）只需要 `INSERT INTO collection_endpoint ...`，不改任何 `.java` 文件，probe 能跑通。

## 六、与前端的关系

平台接入指南（V9 的 `guide_json`）已经在描述"这个平台怎么接"。P1 之后，指南里的 `auth`/`steps` 可以直接从 `endpoint.auth_kinds` 与 `paging` **生成草稿**，减少手工维护两份的问题。
